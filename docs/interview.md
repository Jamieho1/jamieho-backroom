## Private Resume — TKT-121

/interview/resume has an independent single-column editor. Anonymous visitors see only the read-only shared guide and sign-in prompt. Signed-in users without a resume choose Start from template or Start blank; the template is copied once, never linked to subsequent template changes. Each user owns one user_resumes row containing a validated JSON document: entries (role/project/education/certificate/skills/other), plain text fields and nested bullets. Entries and bullets can be added, edited, reordered and removed; certificate/skills shortcuts create those entry types. Save writes the complete document atomically with an expected revision, reports conflicts and retains failed edits for retry. Account changes hide the previous account’s editor before refreshed data arrives.

lib/resume.ts holds strict schemas/limits/order helpers; app/actions/resume.ts derives account IDs server-side; components/interview/resume-editor.tsx renders guide/editor. Limits: 60 entries, 30 bullets each, title/org 160 UTF-16 units, dates/location 80, summary 2,000, bullet 1,000. No identity/publication fields inside documents. No local-storage resume copy, AI generation or PDF export. Existing experience_items/bullets, public journey CV and /behavioral editor are unchanged.

resume_templates has one public default record, seeded empty. Only the owner writes it. Content Drafts supports title/content updates, owner-only on-page preview/outline and approval history/revalidation; private resumes are never draftable. No data is seeded from Jamie’s real CV.
